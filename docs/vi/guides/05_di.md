# Dependency Injection

## Mục tiêu

Bạn đăng ký được bất kỳ class nào với scope đúng, ghép một package mới vào app, và viết lệnh tra cứu sống sót được khi một feature bị gỡ. Khi app ném lỗi "not registered" lúc khởi động, bạn biết cách tìm ra nguyên nhân.

## Điều kiện cần

- **DI được lắp ráp thế nào**: mỗi package một module, thứ tự module mà từng app khai, và vì sao ba vị trí không được xê dịch — [`../architecture/06_app_shell.md` § 3](../architecture/06_app_shell.md#3-lắp-ráp-di--và-vì-sao-thứ-tự-quan-trọng). Hãy đọc trước khi sửa `di_groups` của một manifest.
- Một package có `lib/di/module.dart` — module generator viết sẵn ([`01_new_feature.md`](01_new_feature.md), [`02_new_domain_data.md`](02_new_domain_data.md)).

## 1. Chọn scope

| Annotation | Vòng đời | Dùng cho | Ví dụ thật |
|---|---|---|---|
| `@injectable` | Instance mới mỗi lần resolve | VM / BLoC gắn màn hình | `HomeProfileBloc` |
| `@lazySingleton` | Một instance, tạo khi resolve lần đầu | Controller toàn app, owner của storage | `AuthProvider`, `AuthLocalDataSource` |
| `@singleton` | Một instance, tạo **trong lúc** DI init | Service toàn app không trạng thái; navigator dạng `@Singleton(as: …)` | `AppRouter`, `AppBootStorage`, `AuthNavigatorImpl` |
| `@Injectable(as: I)` | Factory bind vào interface | Đóng góp không state, resolve khi cần | `AuthActionHandlerImpl`, mọi `IFeatureLocalization` |
| `@LazySingleton(as: I)` | Singleton bind vào interface | Repository, route module | `AuthRepositoryImpl`, `NetworkConfigImpl`, `HomeNavDestination` |
| `@module` + `@preResolve` | Khởi tạo bất đồng bộ / thư viện ngoài | Kiểu bạn không sở hữu | `SharedPreferences`, Drift database của chính package |

Controller gắn màn hình không bao giờ là singleton (RULE-10): GetIt giữ nó mãi mãi, nên màn hình rò rỉ bộ nhớ và state bị cũ. Xem [`03_state_management.md`](03_state_management.md) § 9.

Nguyên tắc nhanh: class nào phụ thuộc bất cứ thứ gì từ `domain_*`, `data_*` hay `feature_*` thì để **lazy** (RULE-13, bước 8).

## 2. Nạp state bất đồng bộ trước lần dùng đầu tiên

Class cần setup bất đồng bộ trước khi ai đó dùng tới thì thêm `@PostConstruct(preResolve: true)`:

```dart
@lazySingleton
class AuthLocalDataSource {
  AuthLocalDataSource(this._storageManager);

  final StorageManager _storageManager;

  late final _token = StorageValue<String>(
    _storageManager.getStorage(StorageType.secure),
    AuthStorageKeys.TOKEN,
  );

  late final _authUser = StorageValue<Map<String, dynamic>>(
    _storageManager.getStorage(StorageType.secure),
    AuthStorageKeys.AUTH_USER,
  );

  @PostConstruct(preResolve: true)
  Future<void> initialize() async {
    await Future.wait([_token.readFromStorage(), _authUser.readFromStorage()]);
  }

  // … getter và setter trên _token / _authUser
}
```

`preResolve: true` khiến DI `await` phần setup ngay trong `configureDependencies()`. Sau đó nó đăng ký instance *đã resolve* thành singleton đồng bộ bình thường, nên `getIt<AuthLocalDataSource>()` về sau chạy đồng bộ.

> [!WARNING]
> **`@injectable` + `@PostConstruct` là SAI với owner của storage.** Factory trả instance mới mỗi lần resolve, mỗi cái có **cache trong RAM rỗng**. Getter đồng bộ khi đó trả `null` dù dữ liệu vẫn nằm trên đĩa. Owner của storage bắt buộc phải là `@lazySingleton` hoặc `@singleton` (RULE-45).

## 3. Đăng ký kiểu bạn không sở hữu

Kiểu bạn không sở hữu đi vào container qua một `@module`. `platform/infra/storage/lib/di/module.dart`:

```dart
@module
abstract class CoreStorageDiModule {
  @preResolve
  Future<SharedPreferences> getSharedPreferences() async {
    return SharedPreferences.getInstance();
  }
}
```

`@preResolve` bắt `configureDependencies()` **await** cái này trước khi trả về. Nhờ đó mọi nơi phía sau nhận `SharedPreferences` như một tham số constructor bình thường chứ không phải `Future`. Chỉ dùng nó khi việc khởi tạo thật sự bất đồng bộ; còn lại một getter `@lazySingleton` là đủ.

`@module` cũng là nơi bạn dựng một client từ object của package khác. `modules/auth/data/lib/di/register_module.dart` biến `Dio` dùng chung thành Retrofit data source của module:

```dart
@module
abstract class RegisterModule {
  @lazySingleton
  AuthRemoteDataSource authRemoteDataSource(Dio dio) =>
      AuthRemoteDataSource(dio);
}
```

Gọi `SharedPreferences.getInstance()` hay tự dựng `Dio` ngay trong repository sẽ giấu dependency khỏi container. Nó cũng không chừa khe hở nào để test truyền fake vào. Đó là toàn bộ lý do chúng nằm trong `@module`.

## 4. Bind interface thứ hai vào cùng một instance

> [!WARNING]
> **GetIt resolve theo đúng type đã đăng ký. Nó KHÔNG đi ngược chuỗi supertype** (RULE-14).

Đăng ký `NetworkConfigImpl` `as: NetworkConfig` không làm nó resolve được dưới dạng `SslPinningConfig`, dù `NetworkConfig implements SslPinningConfig`. Hãy bind kiểu thứ hai qua một `@module` — `platform/shell/adapters/lib/di/network_binding_module.dart`:

```dart
@module
abstract class NetworkBindingModule {
  @lazySingleton
  SslPinningConfig bindSslPinningConfig(NetworkConfig config) => config;
}
```

Tham số khai kiểu `NetworkConfig`, nên phép upcast được compiler kiểm tra — không cần ép kiểu `as`. Thiếu binding này, SSL pinning bị bỏ qua mà không báo gì ([`../architecture/06_app_shell.md` § 4](../architecture/06_app_shell.md#vì-sao-sslpinningconfig-cần-binding-riêng)). Cùng pattern đó dùng để đăng ký agnostic stream hai lần — `@singleton` cụ thể cho owner, binding interface cho consumer ([`10_cross_feature.md`](10_cross_feature.md)).

## 5. Resolve đóng góp tuỳ chọn một cách an toàn

Các helper được định nghĩa tại `platform/foundation/kernel/lib/src/di/service_locator.dart` và được `platform/foundation/common/lib/di/module.dart` re-export:

| Helper | Khi chưa đăng ký | Dùng khi |
|---|---|---|
| `getIt<T>()` | **Ném lỗi** | T chắc chắn có — hạ tầng core luôn đi kèm |
| `getItOrNull<T>()` | Trả `null` | T thuộc feature có thể bị gỡ |
| `getAll<T>()` | **Ném lỗi** | Không bao giờ, với đóng góp tuỳ chọn |
| `getAllOrEmpty<T>()` | Trả `const []` | Gom các đóng góp nhiều instance |

```dart
Iterable<T> getAllOrEmpty<T extends Object>({...}) {
  if (!getIt.isRegistered<T>()) {
    return const [];
  }
  return getIt.getAll<T>(...);
}
```

Đây chính là thứ khiến feature gỡ được (RULE-12). App shell gom route, tab và delegate đa ngôn ngữ bằng `getAllOrEmpty`, còn singleton tuỳ chọn thì `getItOrNull` + fallback:

```dart
final tabs = getAllOrEmpty<INavDestinationModule>();          // none composed → []
final entry = getItOrNull<IAppEntryLocation>()?.path;         // none composed → null
final boot = getItOrNull<AppBootStorage>();                   // shell-owned first-launch flag
// Resolved in AppRouter.entryLocation — see 04_routing.md for the full shape.
```

> [!NOTE]
> `getIt.enableRegisteringMultipleInstancesOfOneType()` được gọi trong `configureDependencies()`, trước `getIt.init`. Đó là thứ cho phép nhiều package cùng đăng ký `IFeatureRouteModule` của riêng mình. Thiếu nó, lần đăng ký thứ hai sẽ ném lỗi lúc boot (xem *Xử lý sự cố*).

## 6. Inject qua constructor

Không bao giờ gọi `getIt<T>()` bên trong business logic — ViewModel, Repository, UseCase (RULE-11). Tra cứu ngầm khiến class không test được, vì không truyền fake vào được, và che giấu dependency thật của nó.

```dart
// ĐÚNG — dependency hiện rõ và mock được
@injectable
class LoginUseCase extends BaseUseCase<UserEntity, LoginParams> {
  LoginUseCase(this._authRepository);
  final IAuthRepository _authRepository;
}
```

Chỉ chấp nhận gọi service locator ở các mối nối lắp ráp: `build()` của route, chỗ nối cây widget, và code lắp ráp của app shell.

## 7. Thêm package mới vào DI

1. Tạo `lib/di/module.dart` với `@InjectableInit.microPackage()` (module generator làm sẵn).
2. Gắn annotation cho các class của bạn.
3. Chạy `dart run build_runner build --workspace`.
4. Thêm nó vào `app_manifest.yaml` của app — một module ở mục `modules:`, hoặc một package platform ở đúng mục `di_groups` — rồi chạy `dart tools/composer/composer.dart sync`. Không bao giờ sửa tay `injection.dart`: danh sách module của nó nằm giữa các marker `composer:managed`, và CI Gate 0 fail khi bị lệch (RULE-16).
5. Kiểm chứng bằng smoke test DI (*Kiểm tra* bên dưới). Plugin mà đăng ký của bạn chạm tới trong lúc DI cần test double ở đó (RULE-63).

### Không truyền tham số cho `microPackage()`

Không module nào cần tham số cho `@InjectableInit.microPackage()` (RULE-15), trừ `core_notifications`. Nó truyền `ignoreUnregisteredTypesInPackages: ['firebase_core']`, vì `FirebaseOptions` mà nó inject do `lib/firebase/firebase_module.dart` của từng app đăng ký, không bao giờ do một module của package. Đừng thêm tham số này để che một đăng ký thực sự bị thiếu.

## 8. Chẩn đoán lỗi "not registered" lúc khởi động

> [!CAUTION]
> **`@Singleton` eager không được phụ thuộc type do module chạy sau đăng ký** (RULE-13). Instance được dựng *ngay trong lúc* đăng ký, nên dependency chưa được đăng ký sẽ ném
> `Object/factory with type X is not registered inside GetIt` — ngay lúc khởi động app, mọi lần chạy.
>
> **`flutter analyze` KHÔNG bắt được lỗi này**: đây là lỗi thứ tự lúc chạy. `test/di_smoke_test.dart` của mỗi app boot đồ thị thật cho mọi flavor và bắt nó ở CI Gate 3 (RULE-63).

Để tìm nguyên nhân:

1. Chạy smoke test (*Kiểm tra*). Nó fail và nêu tên kiểu bị thiếu.
2. Mở file generated `apps/mobile/lib/di/injection.config.dart`. File này chỉ chứa thứ tự module: mỗi package một lệnh `…PackageModule().init(gh)`.
3. Mở file generated `lib/di/module.module.dart` của package đăng ký class bị lỗi. Mọi `gh.singleton<...>(...)` ở đó (không có `lazy`) chỉ được gọi `gh<Dep>()` cho type đã đăng ký phía trên nó trong cùng file, hoặc bởi một module có `init` chạy sớm hơn trong `injection.config.dart`.
4. Sửa bằng một từ — `@LazySingleton` — hoặc tốt hơn, bỏ dependency constructor xuyên module. Ca mẫu nằm ở [`../architecture/06_app_shell.md` § 3](../architecture/06_app_shell.md#cái-bẫy-thứ-tự-với-eager-singleton).

## Kiểm tra

```bash
dart run build_runner build --workspace                  # sinh lại mọi module.module.dart
dart tools/composer/composer.dart verify                 # ✅ Generated artifacts are up to date.
cd apps/mobile && flutter test test/di_smoke_test.dart   # All tests passed!
cd apps/admin && flutter test test/di_smoke_test.dart    # All tests passed!
```

Smoke test chạy `configureDependencies()` cho mọi flavor, dựng mọi lazy singleton và resolve mọi contract `core_di`. Một lần chạy xanh mới là bằng chứng đăng ký và thứ tự của bạn đúng; đọc file generated thì không.

Checklist review:

- [ ] Controller màn hình `@injectable`; controller toàn cục `@lazySingleton`
- [ ] Bất cứ thứ gì phụ thuộc type domain/data/feature đều để **lazy**
- [ ] Owner của storage là singleton kèm `@PostConstruct(preResolve: true)`
- [ ] Package mới được ghép trong mỗi `app_manifest.yaml` — module ở mục `modules:`, package platform ở đúng mục `di_groups` — rồi `composer sync`
- [ ] Thứ tự đã được `test/di_smoke_test.dart` của mỗi app kiểm chứng (RULE-13, RULE-63)
- [ ] Tra cứu xuyên feature tuỳ chọn dùng `getItOrNull` / `getAllOrEmpty`
- [ ] Không có `getIt<T>()` trong VM, repository hay use case

## Xử lý sự cố

| Triệu chứng | Nguyên nhân | Cách sửa |
|---|---|---|
| `type X is not registered` lúc khởi động | Eager singleton phụ thuộc module chạy sau | Chuyển sang `@LazySingleton` (bước 8) |
| `getItOrNull<Supertype>()` trả null | GetIt không resolve theo supertype | Thêm binding `@module` (bước 4) |
| Getter storage trả `null` dù đĩa có dữ liệu | Owner là `@injectable`; cache rỗng | Dùng `@lazySingleton` + `@PostConstruct(preResolve: true)` (bước 2) |
| Boot ném `ArgumentError: Type IFeatureRouteModule is already registered inside GetIt.` (hoặc `INavDestinationModule`, `IFeatureLocalization`, `IAppTreeWrapper` — bất kỳ kiểu nào mà nhiều package cùng đóng góp) | Chưa bật đăng ký nhiều instance. GetIt 9 không bao giờ âm thầm giữ lại một cái: lần đăng ký **không tên** thứ hai của một kiểu sẽ ném lỗi trừ khi `allowRegisterMultipleImplementationsOfoneType` được bật | `getIt.enableRegisteringMultipleInstancesOfOneType()` phải chạy trong `configureDependencies()` của app (`apps/<id>/lib/di/injection.dart`, viết tay, nằm ngoài các marker `composer:managed`) **trước** `getIt.init`. Test nào đăng ký hai instance cùng kiểu cũng phải gọi nó (`modules/dashboard/feature/test/dashboard_page_test.dart`) |
| State màn hình cũ khi vào lại | Controller màn hình là singleton | Chuyển sang `@injectable` |
| `getAll<T>()` ném lỗi | Chưa có implementation nào đăng ký | Dùng `getAllOrEmpty<T>()` |
| Đăng ký mới không có hiệu lực | Hot reload không dựng lại đồ thị DI | Chạy lại `build_runner`, rồi **khởi động lại hẳn** app |
