# Dependency Injection

**File này trả lời:** tôi nên dùng annotation nào, module của tôi được đăng ký ở đâu, và vì sao app ném lỗi "not registered" lúc khởi động?

**Đọc xong bạn làm được:** đăng ký bất kỳ class nào với scope đúng, hiểu thứ tự khởi tạo module, tránh bẫy eager singleton, và viết lệnh tra cứu sống sót được khi một feature bị gỡ.

---

## 1. Mô hình: GetIt + Injectable, mỗi package một module

Mỗi package sở hữu một DI module tại `lib/di/module.dart`:

```dart
import 'package:injectable/injectable.dart';

@InjectableInit.microPackage()
void initMicroPackage() {}
```

`build_runner` biến nó thành `lib/di/module.module.dart`, phơi ra ví dụ `CoreStoragePackageModule`. App shell lắp tất cả lại trong `app/lib/di/injection.dart`.

Bạn chỉ cần gắn annotation lên class, nó tự vào module của package đó — không bao giờ phải sửa file generated.

---

## 2. Chọn scope

| Annotation | Vòng đời | Dùng cho | Ví dụ thật |
|---|---|---|---|
| `@injectable` | Instance mới mỗi lần resolve | VM / BLoC gắn màn hình | `HomeProfileBloc` |
| `@lazySingleton` | Một instance, tạo khi resolve lần đầu | Controller toàn app, owner của storage | `AuthProvider`, `AuthLocalDataSource` |
| `@singleton` | Một instance, tạo **trong lúc** DI init | Service toàn app không trạng thái | `AppRouter`, `AppBootStorage` |
| `@Injectable(as: I)` | Factory bind vào interface | Repository có state theo lần dùng | `AuthRepositoryImpl` |
| `@LazySingleton(as: I)` | Singleton bind vào interface | Repository, navigator, route module | `NetworkConfigImpl`, `HomeDashboardTabModule` |
| `@module` + `@preResolve` | Khởi tạo bất đồng bộ / thư viện ngoài | SDK bạn không sở hữu | `SharedPreferences`, `GoogleSignIn` |

> [!CAUTION]
> **Tuyệt đối không đăng ký controller gắn màn hình là singleton.** GetIt giữ nó mãi mãi, nên màn hình rò rỉ bộ nhớ và state bị cũ. Xem [`03_state_management.md`](03_state_management.md) §4.

### `@PostConstruct(preResolve: true)`

Dành cho class cần setup bất đồng bộ trước khi ai đó dùng tới:

```dart
@lazySingleton
class AuthLocalDataSource {
  AuthLocalDataSource(this._storageManager);

  final StorageManager _storageManager;

  late final _token = StorageValue<String>(
    _storageManager.getStorage(StorageType.secure),
    AuthStorageKeys.TOKEN,
  );

  @PostConstruct(preResolve: true)
  Future<void> initialize() async {
    await Future.wait([_token.readFromStorage(), _authUser.readFromStorage()]);
  }
}
```

`preResolve: true` khiến DI `await` phần setup ngay trong `configureDependencies()`, rồi đăng ký lại instance *đã resolve* thành singleton đồng bộ — nên `getIt<AuthLocalDataSource>()` về sau chạy đồng bộ bình thường.

> [!WARNING]
> **`@injectable` + `@PostConstruct` là SAI với owner của storage.** Factory trả instance mới mỗi lần resolve, mỗi cái có **cache trong RAM rỗng**, nên getter đồng bộ trả `null` dù dữ liệu vẫn nằm trên đĩa. Owner của storage bắt buộc phải là `@lazySingleton` hoặc `@singleton`.

## 3. Thứ tự khởi tạo module

Đây là phần hay gây lỗi nhất. `app/lib/di/injection.dart`:

```dart
@InjectableInit(
  externalPackageModulesBefore: [..._coreModules],
  externalPackageModulesAfter: [
    ..._uiModules,
    ..._domainModules,
    ..._dataModules,
    ..._featureModules,
    ..._otherModules,
    ..._databaseModules,
  ],
)
```

Trình tự kết quả:

| # | Nhóm | Nội dung |
|---|---|---|
| 1 | `_coreModules` (**Before**) | common, network, notifications, storage, di |
| 2 | *app-local* | `AppRouter`, `AppProvider`, `DeeplinkProvider`, `AppBootStorage`, `ILanguageStorage`, `IThemeStorage`, `NetworkConfig`, `SslPinningConfig` |
| 3 | `_uiModules` | `CoreBaseUiPackageModule` |
| 4 | `_domainModules` | domain_core, domain_auth, domain_language |
| 5 | `_dataModules` | data_core, data_auth, data_language |
| 6 | `_featureModules` | auth, dashboard, home, onboarding, settings, splash |
| 7 | `_otherModules` | provider / bloc state management |
| 8 | `_databaseModules` | `CoreDatabasePackageModule` |

Hai vị trí là cố ý và **không được "dọn cho gọn"**:

**(a) `CoreBaseUiPackageModule` nằm ở `_uiModules`, không phải `_coreModules`.**
`ThemeProvider` và `LanguageProvider` inject `IThemeStorage` / `ILanguageStorage`, mà implementation của chúng là **app-local** (`app/lib/di/theme_storage_impl.dart`, `language_storage_impl.dart`) nên chỉ được đăng ký ở bước 2. Chạy core_base_ui ở bước 1 sẽ resolve chúng trước khi chúng tồn tại.

**(b) `CoreDatabasePackageModule` chạy CUỐI CÙNG.**
Mở database là `@preResolve`, và chính việc mở đó chạy các bước `IDatabaseMigration` đã gom được. Mọi package đóng góp migration phải đăng ký *trước*, nên module database cố ý xếp sau tất cả module domain, data và feature. An toàn, vì mọi consumer của database đều là lazy singleton — không có gì resolve nó lúc khởi động.

## 4. Bẫy eager singleton

> [!CAUTION]
> **`@Singleton` eager không được phụ thuộc type do module chạy sau đăng ký.** Instance được dựng *ngay trong lúc* đăng ký, nên dependency chưa được đăng ký sẽ ném
> `Object/factory with type X is not registered inside GetIt` — ngay lúc khởi động app, mọi lần chạy.
>
> **`flutter analyze` KHÔNG bắt được lỗi này.** Đây là lỗi thứ tự lúc chạy, không phải lỗi kiểu.

Ca thật: `NetworkConfigImpl` (app-local, bước 2) phụ thuộc `AuthLocalDataSource` nằm ở `data_auth` (bước 5). Đăng ký eager làm app chết ngay lúc boot. Sửa chỉ một từ:

```dart
/// Registered lazily (not eager `@Singleton`) because [AuthLocalDataSource]
/// lives in `data_auth`, whose module is initialized after this app-local DI
/// block runs. Its only consumer, `ApiClient`, is itself `@lazySingleton`,
/// so deferring construction here is safe.
@LazySingleton(as: NetworkConfig)
class NetworkConfigImpl implements NetworkConfig { ... }
```

**Cách kiểm chứng.** Đọc file generated `app/lib/di/injection.config.dart` và kiểm tra mọi `gh.singleton<...>(...)` (không có `lazy`) chỉ tham chiếu type đã đăng ký phía trên nó:

```dart
gh.lazySingleton<_i309.NetworkConfig>(
  () => _i52.NetworkConfigImpl(
    gh<_i700.AuthLocalDataSource>(),
    gh<_i472.ILanguageStorage>(),
    gh<_i693.RefreshTokenUseCase>(),
  ),
);
```

Nguyên tắc nhanh: class nào phụ thuộc bất cứ thứ gì từ `domain_*`, `data_*` hay `feature_*` thì phải để **lazy**.

## 5. Dual registration — bind một instance cho hai interface

> [!WARNING]
> **GetIt resolve theo đúng type đã đăng ký. Nó KHÔNG đi ngược chuỗi supertype.**

`NetworkConfig implements SslPinningConfig`, nhưng vì `NetworkConfigImpl` chỉ đăng ký `as: NetworkConfig` nên `getItOrNull<SslPinningConfig>()` trả `null` — khiến `AppInitializer` **âm thầm bỏ qua** certificate pinning ở staging và production. Cách sửa, `app/lib/di/network_binding_module.dart`:

```dart
@module
abstract class NetworkBindingModule {
  @lazySingleton
  SslPinningConfig bindSslPinningConfig(NetworkConfig config) => config;
}
```

Tham số khai kiểu `NetworkConfig`, nên phép upcast được compiler kiểm tra — không cần ép kiểu `as`. Cùng pattern đó dùng để đăng ký agnostic stream hai lần (`@singleton` cụ thể cho owner, binding interface cho consumer) — xem [`10_cross_feature.md`](10_cross_feature.md).

### Bind SDK bên thứ ba

Cơ chế `@module` cũng chính là cách đưa các singleton của SDK vào container. `packages/data/auth/lib/di/register_module.dart`:

```dart
@module
abstract class RegisterModule {
  @preResolve
  Future<GoogleSignIn> get googleSignIn async {
    final instance = GoogleSignIn.instance;
    await GoogleSignIn.instance.initialize();
    return instance;
  }

  @lazySingleton
  FirebaseAuth get firebaseAuth => FirebaseAuth.instance;

  @lazySingleton
  FirebaseFirestore get firestore => FirebaseFirestore.instance;

  @lazySingleton
  FacebookAuth get facebookAuth => FacebookAuth.instance;
}
```

`AuthRepositoryImpl` sau đó nhận cả năm cộng tác viên qua tham số constructor. Gọi `FirebaseAuth.instance` bên trong repository sẽ giấu phụ thuộc khỏi container và không chừa khe nào để truyền fake khi test — `@preResolve` chỉ cần cho đúng SDK nào đòi thiết lập bất đồng bộ.

## 6. Các helper resolve

Định nghĩa tại `packages/core/common/lib/di/module.dart`:

| Helper | Khi chưa đăng ký | Dùng khi |
|---|---|---|
| `getIt<T>()` | **Ném lỗi** | T chắc chắn có — hạ tầng core luôn đi kèm |
| `getItOrNull<T>()` | Trả `null` | T thuộc feature có thể bị gỡ |
| `getAll<T>()` | **Ném lỗi** | Không bao giờ, với đóng góp tuỳ chọn |
| `getAllOrEmpty<T>()` | Trả `const []` | Gom các đóng góp nhiều instance |

```dart
Iterable<T> getAllOrEmpty<T extends Object>({...}) {
  if (!getIt.isRegistered<T>()) {
    return const [];
  }
  return getIt.getAll<T>(...);
}
```

Đây chính là thứ khiến feature gỡ được. App shell gom route, tab và delegate đa ngôn ngữ bằng `getAllOrEmpty`, còn singleton tuỳ chọn thì `getItOrNull` + fallback:

```dart
final entry = getItOrNull<IAppEntryLocation>()?.path;
if (entry != null) return entry;
```

> [!NOTE]
> `getIt.enableRegisteringMultipleInstancesOfOneType()` được gọi trong `configureDependencies()` — đó là thứ cho phép nhiều package cùng đăng ký `IFeatureRouteModule` của riêng mình.

## 7. Chỉ dùng constructor injection

> [!CAUTION]
> **Tuyệt đối không gọi `getIt<T>()` bên trong business logic** — ViewModel, Repository, UseCase. Tra cứu ngầm khiến class không test được (không truyền fake vào được) và che giấu dependency thật của nó.

```dart
// ĐÚNG — dependency hiện rõ và mock được
@injectable
class LoginUseCase extends BaseUseCase<UserEntity, LoginParams> {
  LoginUseCase(this._authRepository);
  final IAuthRepository _authRepository;
}
```

Chỉ chấp nhận gọi service locator ở các mối nối lắp ráp: `build()` của route, chỗ nối cây widget, và code lắp ráp của app shell.

## 8. Thêm package mới vào DI

1. Tạo `lib/di/module.dart` với `@InjectableInit.microPackage()` (module generator làm sẵn).
2. Gắn annotation cho các class của bạn.
3. Chạy `dart run build_runner build -d --workspace`.
4. Import module generated trong `app/lib/di/injection.dart` và thêm `ExternalModule(YourPackageModule)` vào **đúng nhóm** (`_domainModules`, `_dataModules`, `_featureModules`, …).
5. Kiểm tra lại thứ tự trong `injection.config.dart`.

### `ignoreUnregisteredTypes`

Khi module tham chiếu type được đăng ký nơi khác, hãy liệt kê nó trong `ignoreUnregisteredTypes` và import bằng đường dẫn **tương đối** từ barrel của package (ví dụ `import '../domain_auth.dart';`) để thoả lint `prefer_relative_imports`.

## 9. Xử lý sự cố

| Triệu chứng | Nguyên nhân | Cách sửa |
|---|---|---|
| `type X is not registered` lúc khởi động | Eager singleton phụ thuộc module chạy sau | Chuyển sang `@LazySingleton` (§4) |
| `getItOrNull<Supertype>()` trả null | GetIt không resolve theo supertype | Thêm binding `@module` (§5) |
| Getter storage trả `null` dù đĩa có dữ liệu | Owner là `@injectable`; cache rỗng | Dùng `@lazySingleton` + `@PostConstruct(preResolve: true)` (§2) |
| Chỉ gom được một đóng góp | Chưa bật đăng ký nhiều instance | `enableRegisteringMultipleInstancesOfOneType()` phải chạy trước `getIt.init` |
| State màn hình cũ khi vào lại | Controller màn hình là singleton | Chuyển sang `@injectable` |
| `getAll<T>()` ném lỗi | Chưa có implementation nào đăng ký | Dùng `getAllOrEmpty<T>()` |

## Checklist

- [ ] Controller màn hình `@injectable`; controller toàn cục `@lazySingleton`
- [ ] Bất cứ thứ gì phụ thuộc type domain/data/feature đều để **lazy**
- [ ] Owner của storage là singleton kèm `@PostConstruct(preResolve: true)`
- [ ] Module mới được thêm đúng nhóm trong `injection.dart`
- [ ] Đã kiểm tra thứ tự trong `injection.config.dart` generated
- [ ] Tra cứu xuyên feature tuỳ chọn dùng `getItOrNull` / `getAllOrEmpty`
- [ ] Không có `getIt<T>()` trong VM, repository hay use case
